# SA HR Bot — план работ

## Реализовано в `main`

- [x] **Доступ.** Регистрация по одноразовому коду. Два календарных месяца с момента первого использования. Для ранее выданных и использованных кодов миграция берёт дату регистрации. Новый свободный код продлевает доступ и возвращает пользователя к сохранённому шагу. Админские команды доступны при истёкшем пользовательском доступе.
- [x] **Онбординг.** Приветствие с картинкой и формулировкой «174 вопроса», четыре вопроса квалификации, подтверждение и редактирование анкеты, урок КДИР с картинкой и видео. Текущий грейд может быть джуном, мидлом или сеньором, целевой — мидлом или сеньором.
- [x] **Банк вопросов.** Активный CSV Кати содержит 58 основных вопросов с контекстом и двумя уточнениями на каждый. Мидлы и сеньоры получают вопросы из одного банка. Бот синхронизирует CSV с PostgreSQL при старте, сохраняет историю попыток и исключает повторы в сессии. Исходник и предыдущие банки лежат в `materials/`.
- [x] **Тренировка.** Основной вопрос и два уточнения из одного блока, короткая обратная связь по каждому ответу и общий разбор. После блока можно выбрать направление, закончить тренировку или продолжить после итога. При исчерпании банка бот предлагает итог. Повторный `/start` с личным кодом позволяет начать заново с сохранением истории.
- [x] **Обратная связь.** Обращение на «вы», нейтральный тон, разные ожидания от мидла и сеньора. Пример из банка служит ориентиром, КДИР — рекомендацией. Инструкции требуют учитывать логичные альтернативные ответы, сверять замечания с тем, что сказал кандидат, и отмечать существенный пробел только при его наличии.
- [x] **Хранение прогресса.** PostgreSQL хранит профиль, состояние сессии, ответы, обратную связь, слабые зоны и итог. Для сессии действует ограничение на одну активную запись на пользователя. Сохранённую обратную связь и итог можно отправить повторно после сбоя Telegram без нового вызова LLM.
- [x] **Администрирование.** Доступ по `ADMIN_IDS`. Работают `/admin`, `/code`, `/codes`, `/delete_code`, `/tokens КОД` и `/report` с CSV для длинных отчётов. PostgreSQL хранит число вызовов и входные, выходные, суммарные и кешированные токены по пользователю, сессии и типу операции.
- [x] **Разработка и выкладка.** Есть сценарные и интеграционные тесты, проверка миграций и повторного импорта банка в CI, Dockerfile, примеры окружения и Compose. Запуск и резервное копирование перед обновлением описаны в [README](../README.md), пользовательский сценарий — в [workflow](workflow-new.md), ручные проверки — в [инструкции](how-to-test.md). Первоначальный сценарий сохранён в [исходном workflow](Workflow-by-DanyaClaude.md).

## Отдельная ветка `free` — бот с доступом по подписке

### Сделано

- [x] Создана ветка `free` от `main` для второго бота.
- [x] Первый `/start` показывает утверждённое приветствие про 58 вопросов с `pic1.PNG`. Кнопка «Подписаться на канал» открывает https://t.me/sa_jelatinka, «Я готов» проверяет подписку. При отсутствии подписки бот показывает утверждённый текст, ссылку и кнопку «Я в деле». При сбое Telegram можно повторить проверку.
- [x] После успешной проверки бот регистрирует пользователя по Telegram ID, отправляет вступление про экзамен на права, затем вопрос «Какой у тебя текущий грейд?». Проверка нужна при первом входе. Повторная кнопка не сбрасывает активную сессию.
- [x] Убраны регистрация, продление и перезапуск по коду. Для сохранённой сессии `/start` предлагает продолжить или начать заново. Квалификация, урок КДИР, банк и тренировка переиспользованы из `main`.
- [x] Сохранены `ADMIN_IDS` и `/admin`. Команды управления кодами удалены. `/tokens TELEGRAM_ID` показывает расход пользователя, `/report` — число пользователей, общий расход и разбивку по каждому, включая нулевой расход. Длинный отчёт приходит в CSV.
- [x] Подготовлены отдельный проект Docker Compose, настройки отдельной PostgreSQL и инструкция запуска, обновления и отката второго бота на VPS.
- [x] Пройдены тесты входа, повторной проверки, ошибки Telegram, полного пути до итога и отчётов. На временной PostgreSQL проверены миграции, регистрация и отчёты. Два импорта подряд загрузили по 58 вопросов. Сборка и статическая проверка прошли.
