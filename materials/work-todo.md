### Зафиксированные продуктовые решения

- [x] Таблица Кати полностью заменяет действующий банк, а не объединяется с ним.
- [x] `Джун` остаётся доступен как текущий уровень кандидата, но целевой уровень можно выбрать только `мидл` или `сеньор`.
- [x] Вопросы не делятся на мидла и сеньора: один и тот же вопрос доступен обоим уровням.
- [x] Разница между мидлом и сеньором задаётся ожиданиями от ответа, а не отдельной разметкой каждой строки исходной таблицы.
- [x] Из трёх дожимов используются только два; для MVP берём первые два по порядку в таблице, третий сохраняем только в исходнике.
- [x] Ответ из таблицы является примером хорошего ответа, а не единственным правильным вариантом.
- [x] Другой ответ принимается, если он по смыслу верен, относится к вопросу и логично аргументирован.
- [x] После слабого ответа бот отмечает полезную часть, называет один главный пробел и даёт короткую подсказку или пример.
- [x] КДИР является рекомендацией. Отсутствие формулы не делает технически верный ответ неправильным; бот только коротко напоминает о ней.
- [x] Бот не требует деталей, которых не было в вопросе, не выдумывает обязательные сущности и кейсы и не называет необязательные детали «критичными».
- [x] Бот не требует описывать словами внешний вид диаграммы. Он может оценить назначение, состав и связи только в пределах заданного вопроса.

### Нужен ли Docker

Docker не обязателен. Для разработки достаточно уже установленного PostgreSQL через Homebrew. Это самый короткий путь на этом Mac.

Docker пригодится, если хочется изолированную, легко пересоздаваемую БД и окружение, похожее на production. Не нужно одновременно держать PostgreSQL Homebrew и контейнер на одном порту `5432`.

Вариант A, использовать PostgreSQL из Homebrew:

```bash
brew services restart postgresql@15
pg_isready
createdb sa_hr_bot
psql -d sa_hr_bot -c 'select version();'
```

Если `pg_isready` снова не отвечает, проверить состояние и лог сервиса:

```bash
brew services list
brew services info postgresql@15
```

Вариант B, установить Docker Desktop через Homebrew:

```bash
brew install --cask docker
```

После установки нужно один раз открыть Docker Desktop и дождаться запуска engine. Затем проверить:

```bash
docker --version
docker compose version
docker info
```

Docker Desktop также можно скачать с официального сайта Docker. Установка через Homebrew удобнее тем, что приложение потом проще обновлять командой Homebrew. Для этого проекта отдельная ручная установка PostgreSQL с сайта не нужна.

### Минимальная подготовка локальной БД

После выбора Homebrew PostgreSQL или Docker PostgreSQL:

1. Создать пустую БД (locally сейчас используется `sahrbot`).
2. Указать корректный `DATABASE_URL` в `.env`.
3. Применить миграции командой `make migrate` (бот также применяет их при старте).
4. Импортировать `materials/question_bank.csv` утилитой `cmd/import-questions`.
5. Сгенерировать хотя бы один одноразовый код утилитой `cmd/generate-codes`.
6. Только после исправления критичных проблем ниже запускать полноценное интервью в Telegram.

Полезные команды для будущей проверки, когда код будет готов:

```bash
go test ./...
go vet ./...
go build ./...
make migrate
go run ./cmd/import-questions -file materials/question_bank.csv
go run ./cmd/generate-codes -n 1
go run ./cmd/bot
```

Последняя команда запускает long polling и начнёт обращаться к Telegram, OpenAI и БД. Не запускать её случайно с production-токеном.
